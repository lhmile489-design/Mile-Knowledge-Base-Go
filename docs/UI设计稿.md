# UI 设计稿：页面、流程与状态清单

> 状态：阶段 05 已审核通过 v1.0（用户 2026-11-18 确认）。
> 适用：PRD v1.2 R1 重构对齐版。
> 设计来源：旧版 Mile Knowledge Base v2.7.0 的运行截图。截图是在沙箱里运行旧版最新构建 `out/`（2026-11-17 20:16）得到的，截图与清单在 [`design/baseline/`](../design/baseline/)。
> 原则：重写版的 UI、UX 与布局与旧版一致（PRD G2），本阶段不重新做视觉设计。截图是视觉定稿，本文件说明页面结构、入口与返回、状态覆盖，以及哪些地方截图表达不了。

## 1. 导航与页面层级

```text
应用窗口（单窗口，无边框，自绘 40px 标题栏）
├── 欢迎页            —— 没有可打开的知识库时
│   └── 新手引导（2 步）
└── 工作台            —— 打开知识库后
    ├── 左：侧栏（知识库树、搜索入口、底部：操作日志 / 导入技能 / 设置）
    ├── 中：对话区（永远展开）
    │   ├── 历史栏（可开合，200px）
    │   ├── 空状态 = 总览磁贴
    │   └── 输入框与运行参数条
    ├── 右：文档面板（可折叠为 40px 竖轨）
    │   ├── 搜索面板（Ctrl+P，顶部）
    │   ├── 标签栏 + 编辑器（阅读 / 源码 / 分栏）
    │   └── 反向链接、来源追踪等小节
    └── 覆盖层：设置页、技能导入向导、健康面板、会话信息浮层、操作日志面板
```

- 栏宽：侧栏默认 232（192–320），文档面板默认 560（320–800），中间对话列最小 480，栏间 8px 缝即拖拽条（PRD FR-SET）。
- 窗口变窄时先压缩文档面板，不压缩对话列。
- 覆盖层（设置、导入向导）位于标题栏下方，不是路由跳转；关闭后回到原工作台状态，栏宽、展开的目录、打开的标签都保持不变。

## 2. 入口、返回与跨页面上下文

| 视图 | 入口 | 返回 / 关闭 | 保持的上下文 |
| --- | --- | --- | --- |
| 欢迎页 | 启动时没有可用知识库；移除最后一个知识库 | 打开任一知识库 | 最近知识库列表 |

## 4. 反馈、确认与恢复

规则以 PRD 第 8、9 节为准，这里只列截图中能看到的位置：

- 错误、警示、信息都是行内卡片（1px 状态色边框，不染底色），没有全局 Toast。
- 危险操作：变更计划卡 → 确认；永久删除多一层「我了解风险」；删除历史、删除供应商使用两步确认，并有 600ms 时间门。
- 未保存：关闭标签、切换文档、离开设置、关闭窗口都要先确认。
- 恢复：操作日志里每条已完成事务带「恢复」。

## 6. 边界检查

| 边界 | 旧版表现 | 新版要求 |
| --- | --- | --- |
| 长文件名 | 截断加悬停提示 | 一致 |

## 7. 需求缺口与同步

截图过程中发现与 PRD 不一致的地方，记录在这里，经用户确认后回写 PRD：

| 发现 | 涉及 | 处理 |
| --- | --- | --- |
| 所有已登记知识库都断开时，旧版不显示欢迎页，而是进入工作台的「知识库不可用」状态（标题栏「未选择知识库」）；欢迎页只在没有 activeVaultId 时出现（旧版 `App.tsx:101`） | PRD 5.1 欢迎页的进入条件 | 用户决定新版改为显示欢迎页（与旧版不同），已写入 PRD v1.3 与 D-006；此状态没有旧版截图，以截图 00 的欢迎页 + 已断开卡为准 |
| 库内图片与相对链接以**知识库根**为基准解析，不以文档所在目录为基准（旧版 `imageSource.ts:152-180`、`readerLinks.ts`）；粘贴图片插入的路径 `raws/attachments/...` 也是相对库根，所以旧版自洽。截图 16 中 `attachments/img.png` 显示「图片文件不存在」即为此 | PRD FR-DOC 图片、FR-LINK href | 已确认按旧版，写入 PRD v1.3 |
| 阅读模式把 YAML frontmatter 当正文渲染（截图 16 顶部的「title: … tags: …」被渲染成标题），旧版 react-markdown 没有处理 frontmatter | PRD FR-DOC 阅读渲染；markdown-render-pipeline skill | 已确认原样复刻，写入 PRD v1.3 与 D-006 |
| 路由到不同 Agent 的消息各自成为独立会话 | FR-AI-HIST | 与 PRD「4 个 Agent 各自有独立会话」一致，无需修改 |
