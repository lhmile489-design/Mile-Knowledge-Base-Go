## 1. 背景、问题与依据

### 1.1 为什么重写

旧版用 Electron 39 + React 19 实现，功能完整、日常在用，但用户反馈经常卡死、性能低。用户决定改用 egoist/mygo（Go 后端 + 系统 WebView2）+ React 重写。功能、UI/UX、布局与旧版保持一致。

### 1.2 卡死与慢的根因分析

以下结论来自对旧版代码的静态分析。旧版没有留下实测性能数值，所以标「推测」的条目需要在新版用基准测试验证，不能当作已证实。

| 编号 | 机制 | 位置（旧版） | 证据级别 |
| --- | --- | --- | --- |
| P-1 | 外部保存或 Agent 批量写入 N 个文件时，每个文件都触发：realpath + stat + 读文件 + 全库链接图重投影 + 整个索引快照 JSON 重写。全部在 Electron 主进程事件循环串行执行，主进程被占满后整个窗口不响应 | `src/main/index.ts:539-570`，`IndexService.ts:208-244, 695-732, 835-858` | 机制有代码证据；卡死程度为推测 |
| P-2 | 索引快照没有去抖、不增量，每次变更都整份序列化写盘；万级文档时一次写入达到 MB 级 | `IndexService.ts:835-858` | 代码证据 |
| P-3 | 流式输出时每一帧都对正在生成的整条回答做完整 Markdown 解析，并重新分组整段对话 | `agentStore.ts:204-231`，`AgentTranscript.tsx:56-57,174-184`，`ChatMarkdown.tsx` | 代码证据；旧版计划文档实测单条 9832 字每次 6.7–9.9ms |
| P-4 | 长列表没有虚拟化：文件树、搜索结果、对话历史、操作日志、历史查看器 | `TreeNode.tsx`，`ConversationHistory.tsx:438-485` 等 | 旧版实测历史查看器 50 条长回答 172–189ms |
| P-5 | 每个 token 都跨进程传 3 次（引擎进程 → 主进程 → 渲染进程），没有节流 | `engineServer.ts:103`，`EngineHost.ts` | 代码证据 |
| P-6 | 监听与索引只排除 `node_modules`、`.git`、`.mile-kb`；知识库里的大型代码仓库会被全量监听和索引。chokidar 首轮扫描与索引快照解析都排在窗口显示之前 | `index.ts:653-663` | 代码证据；耗时为推测 |
| P-7 | 文件树逐项串行 stat，目录还要额外 readdir 取子项数；操作日志、事务清单每次写入都整份重写 | `VaultService.ts:267-276`，`AuditLedger.ts:144-158`，`TransactionService.ts:144` | 代码证据 |
| P-8 | CodeMirror 外部值变化时整篇替换；Agnes 抽屉订阅整个 agents 对象，每个 token 重渲染整棵抽屉 | `MarkdownEditor.tsx:132`，`AgnesDrawer.tsx` | 代码证据 |

### 1.3 事实、假设与依据

- 事实：旧版功能清单、数值上限、交互规则均来自源码，见各功能节的「旧版行为」。
- 假设：Go 后端承担 IO 与计算、WebView 只做渲染后，上述 P-1 到 P-7 不会再阻塞界面。这需要新版用第 10 节的指标实测证明。
- 未知：旧版在用户真实知识库上的启动时间、内存占用、检索耗时都没有记录。新版首个可运行版本应在相同知识库上同时测旧版，作为对比基线。

## 6. 功能需求

以下每一节是一个功能。数值和规则如无特别标注均为「旧版行为」。

### FR-WIN 窗口、标题栏、托盘与关窗

- 单窗口应用。默认 1440×900；最小宽 744px，等于侧栏最小 192 + 对话最小 480 + 文档竖轨 40 + 间隙 32；最小高 640。
- 无系统标题栏，自绘 40px 标题栏。左侧：18px 应用图标、「Mile Knowledge Base」、等宽大写「VAULT」小标签。中间：当前知识库名，过长截断。右侧：主题分段控件（浅色 / 深色 / 系统）和最小化、最大化 / 还原、关闭按钮。整条可拖动，交互元素不可拖动。
- 窗口准备好再显示；显示前窗口底色按当前主题设为画布色，不出现白闪。
- 托盘图标始终存在。菜单项「显示主窗口」「退出」；单击托盘图标显示主窗口。
- 关窗行为（设置 → 常规）：
  - 每次询问（默认）：弹框「挂到托盘 / 退出应用」，带「记住我的选择」复选框；取消按「挂到托盘」处理；
  - 挂到托盘：隐藏窗口，进程继续运行；
  - 退出应用：结束进程。
- 托盘创建失败时，「挂到托盘」按退出处理，避免窗口藏起来后再也找不回。
- 有未保存文档时，先弹「继续编辑 / 丢弃并关闭」，再走关窗行为。
- 新增约束：mygo 的托盘与原生对话框能力需要在阶段 07 验证；做不到与旧版一致时，先报告再改方案，不静默降级。

### FR-THEME 主题

- 三档：浅色、深色、跟随系统；默认跟随系统；存在应用设置里。
- 根元素带解析后的 `data-theme`。切换的那一帧关闭过渡，避免颜色逐个擦除。
- 设置页给浅色、深色各一个主题缩略图，缩略图独立上色，不随当前主题变。
- 窗口底色：浅色 `#eceef1`，深色 `#0e0f11`，与令牌 `--raw-canvas` 一致。旧版主进程里另有 `#F6F7F9` / `#0B0F14` 两个值，与令牌不一致；新版以令牌为准，见第 13 节 Q6。

### FR-VLT 知识库

- 知识库 id 由目录真实路径的 SHA-256 前 16 位派生；同一路径只登记一次。最近知识库最多 12 个。
- 打开、切换：系统对话框选目录；按 id 打开时更新「上次打开时间」并记为「上次知识库」；启动时自动打开上次知识库。
- 移除：停止监听，清除该库的 revision 和最近文档；对话历史保留。
- 断开：根目录不存在或无权限时，不进入可用列表，以「已断开」显示（原因只分「不存在」「无权限」），提供重试和移除；记录保留，只有移除才删除。
- 所有已登记知识库都断开时（包括上次知识库断开、启动时无库可开），显示欢迎页，已断开的知识库以故障卡显示。旧版此时进入工作台的「知识库不可用」空壳（旧版 `App.tsx:101`）；新版有意改为欢迎页（v1.3，D-006）。
- 新建向导：
  - 选择目录。目录非空时默认不建脚手架，除非用户勾选确认。判断非空时忽略 `.ds_store`、`thumbs.db`、`desktop.ini`；点号开头的项算内容。
  - 6 个规范目录都不存在时，建 `raws/`、`_archives/`、`projects/`、`tools/`、`AI Knowledge base/`、`dev-constraints/`，各放一个自描述 README.md。
  - 不建 `skills/`，也不建任何点号目录。
  - 可重复执行，已存在的目录跳过。
- 选目录得到的 token 有效期 10 分钟；前端拿不到绝对路径。
- 欢迎页：
  - 主卡「选择一个知识库」，含唯一强调按钮「选择目录」和「新建知识库向导」；
  - 最近知识库卡最多 6 张，已断开的卡带故障边框以及重试、移除按钮；
  - 脚注说明还有几个没显示。

### FR-TREE 文件树

- 懒加载，每次只读一层。目录在前、文件在后；组内按名称排序，大小写不敏感。
- 一级目录是吸顶的分区标题，带主题图标；skills 分区显示分类计数。
- 行内容：展开箭头（旋转动画）、别名、「未索引」标注、子项数。
- 操作按钮在悬停或聚焦时出现：重命名、别名（仅目录）、归档、删除。所有操作都生成变更计划，没有原生右键菜单。
- 侧栏顶部：知识库名、新建文件按钮、新建目录按钮、整条「搜索 Ctrl P」入口。底部固定块：操作日志、导入技能、设置。
- 拖放：拖到目录上生成移动计划；不能拖进自身或子树。
- 内联新建、重命名、别名编辑：Enter 提交，Esc 取消；重命名时默认选中主干名，不选扩展名。
- 命名校验：
  - 不能为空，≤200 字符；
  - 禁用字符 `<>:"|?*\/` 和控制字符；
  - 不能是 `.` 或 `..`；不能以点或空格结尾；
  - 不能用 DOS 保留名（con、prn、aux、nul、com1-9、lpt1-9，按扩展名前的基名判断）；
  - 同级重名按大小写不敏感判定冲突；
  - 新建文件没有扩展名时补 `.md`。
- 新增约束：树必须虚拟化，单个展开目录有 10 000 个子项时滚动不卡（NFR-PERF）。

### FR-DOC 文档编辑与阅读

- 标签栏：
  - 高 30px，超出时横向滚动；
  - 可拖拽重排；双击标签置顶；
  - 脏标记是 5px 圆点，带读屏文字；
  - 关闭有未保存修改的标签要确认；关掉最后一个标签时回到空状态。
- 工具栏（34px）：图标、路径、脏点、模式分段（阅读 / 源码 / 分栏）、保存状态、revision / 换行风格 / 大小、保存按钮。
- 三种模式，默认阅读：
  - 阅读：真正的排版，正文最大宽 70ch 居中，只读；键入和 Ctrl+S 都不改文件。
  - 源码：等宽 13px、行高 1.65、带行号，不做语法着色或装饰。
  - 分栏：左边源码，右边阅读，中间 1px 分隔线。
  - 切换模式不重新序列化文本，保存写回的就是输入的原始字节，例如 `__下划线__` 不会变成 `**星号**`。
- 编辑器：撤销历史、默认快捷键、Ctrl+F 查找（面板在顶部）、选中文字的同词高亮、Tab 缩进、自动换行、Ctrl+S 保存；Ctrl / Cmd + 点击 wikilink 跳转或新建；粘贴或拖入图片会保存图片并插入链接。
- 阅读渲染：
  - 文档开头的 YAML frontmatter 不做特殊处理，按普通 Markdown 渲染（旧版行为，例如 `title: …` 加下一行 `---` 会渲染成二级标题）。本期原样复刻（v1.3，D-006）；检索侧照常从 frontmatter 取标题和标签。
  - 支持 CommonMark + GFM：表格、任务列表、删除线、自动链接；
  - 支持 wikilink；
  - 原始 HTML（块级、行内、注释）不渲染也不执行，而是**转义成文字原样显示**，例如 `<b>粗</b>` 显示为文字「<b>粗</b>」（旧版 react-markdown 实测行为，v1.4 修正，见 spikes/r3-render）；
  - 标题不生成锚点 id（旧版行为）；
  - 任务列表复选框只读；
  - 缺失的链接显示「（未创建）」，同名多个的显示「（有多个同名）」，样式为灰色虚线。
- 编码与写入：
  - 只接受严格 UTF-8，否则报「不支持的编码」；
  - 读取时记下 BOM 和主导换行风格；
  - 写回时还原原文件的 BOM 和换行风格；
  - 原子写入：同目录写临时文件后改名，保留原文件权限。
- 阈值：
  - 超过 1 MiB 不进阅读模式，阅读按钮禁用并给出提示；
  - 超过 2 MiB 只读预览；
  - 单次写入上限 2 MiB，超过就拒绝，不截断。
- 冲突与外部修改：
  - revision 指纹由大小、修改时间、SHA-256 组成。
  - 保存时如果 revision 不符，就不写盘，显示冲突卡，提供 3 个选择：保留当前、采用磁盘（要两步确认）、合并比较（双栏对照）。
  - 文档没有未保存修改时，外部改动直接提示有新版本；有未保存修改时显示「磁盘有新版本」信息卡。
  - 切换文档时如有未保存修改，先确认。
- 图片：
  - 按文件头识别 png、jpg、gif、webp、bmp、avif，不收 SVG 和 ICO；上限 8 MiB；
  - 保存到 `raws/attachments/pasted-<sha256前12位>.<ext>`，同一张图只存一次；
  - 阅读模式中，库内相对路径的图片显示；**相对路径以知识库根目录为基准**，不以文档所在目录为基准（旧版 `imageSource.ts:152-180`，v1.3 写明）；`data:image/*` 直接显示；
  - https 远程图片默认显示占位卡，点击后才加载；http 图片拦截。
- 新增约束：外部修改合并进编辑器时用差异更新，不整篇替换（P-8）；图片字节经 `kbimg` 协议 POST 上传，不经 base64 跨进程传输（API.md §5、M19；decisions.md D-009 第 1 条）。

### FR-LINK 链接

- 语法：`[[目标]]`、`[[目标|别名]]`、`[文字](目标)`。图片语法不算链接。代码块和行内代码里的链接不抽取。
- 解析按以下顺序，某一层只有唯一命中才算解析成功：
  1. 精确相对路径，可以省略扩展名；
  2. 文件名；
  3. 标题。
- 多个候选时报「候选 N 个」，不自动挑；没有候选就是断链。
- 反向链接只算已解析的边，排除自己引用自己。系统区文档不参与链接图。
- 新建未创建的链接：目标含 `/` 时相对库根，否则放同目录；没有扩展名时补 `.md`；每一段都要过命名校验，不合法就不提供新建；新文件内容是 `# <名字>`。
- 阅读模式中的 href：
  - http(s)：用系统浏览器打开；
  - `#xx`：页内锚点链接，显示为链接样式，点击不做任何事（旧版 `readerLinks.ts:31`，v1.4 写明）；
  - 库内相对路径（去掉 `?` 和 `#` 后解码，**以知识库根目录为基准**）：在应用内打开；
  - `..`、绝对路径、盘符、UNC、`javascript:`、`file:`、`mailto:` 等其他一律显示为普通文字。
- 反向链接面板在文档面板底部，列出反向链接和未解析链接及原因。
- 新增约束：文件变更时只重算受影响文档的链接，不能每次重投影全库（P-1）。

### FR-SRCH 检索

- 索引范围：
  - 递归遍历知识库，排除 `node_modules`、`.git`、`.mile-kb`；
  - 只有以下扩展名读正文：md、markdown、txt、json、yaml、yml、toml、ts、tsx、js、jsx、py、go、java、rs、sh、css、html；
  - 非 UTF-8 或超过 2 MiB 的文件只索引路径。
- 标题取 frontmatter 的 title；没有就取第一个标题行；再没有就用文件名。frontmatter 只解析扁平的 `key: value` 和 tags，tags 支持列表、`[a,b]`、`a,b` 三种写法。
- 分词：
  - 连续中日韩文字切成二元组，保留单字，不跨标点；
  - 英文和数字保留词内的 `.`、`-`、`+`、`#`，例如 `v4.1`、`c#`；
  - 统一小写并去重；超过 20 万字符截断；
  - 路径的每一段按整词、分词、`.-_` 拆分三种方式入索引。
- 打分（v1.1 修订）：改用 SQLite FTS5 的 bm25，按字段加权（建议沿用旧版的权重比例：标题 12、标签 8、标题行 6、路径 4、正文 1，阶段 07 实测后调整）。排序结果不要求与旧版逐条一致。
  - 旧版行为供参考：任一词命中即召回；多词且全部命中时分数乘 2。
  - 匹配理由保留：显示命中了哪些字段，即标题、标题段、标签、路径、正文。
- 排序：相关度（同分按路径）、更新时间、路径。
- 过滤：功能区、扩展名、标签、时间档（全部 / 1 天 / 7 天 / 30 天）、是否包含系统区（默认不包含）。
- 限制：
  - 查询超过 200 字符截断；
  - 默认返回 50 条，最多 200 条；
  - 片段取首个命中位置前后各 60 字符，找不到就留空，不伪造；
  - 高亮按大小写不敏感的字面匹配；
  - 查询不编译成正则；
  - 索引未就绪时返回部分结果，并标注「索引未完成」。
- 搜索面板：
  - Ctrl+P 打开，位于文档面板顶部，最大高度 420px；
  - 包含输入框、排序分段、功能区筛选、时间档、扩展名快选（md / txt / ts）、清除过滤、已选标签；
  - 每条结果显示图标、标题、时间、等宽路径、两行片段（含高亮）、匹配字段、标签；
  - ↑↓ 选择，Enter 打开，Esc 关闭；
  - 底部显示「N 条 · X ms」。
- 索引持久化（v1.1 修订）：
  - 使用 SQLite，存放在应用数据目录，每个知识库一个库文件，属于派生数据，可以删除重建；
  - 旧版的 `index-<vaultId>.json` 不读取也不迁移；
  - 必须满足：增量更新；变更合并成事务写入；首次建索引在后台进行，不阻塞界面（P-1、P-2）。
  - 是否在索引中存正文副本供 FTS5 使用，阶段 08 决定。这不违背「文件是唯一事实源」：索引只是可重建的派生数据。

### FR-MUT 变更计划、事务、操作日志与恢复

- 共 8 种操作：新建文件、建目录、编辑、移动、复制、归档、移到回收站、永久删除。
- 计划规则：
  - 一个计划最多 500 项；
  - 目标已存在一律拒绝，唯一例外是只改大小写的重命名；
  - 归档移到 `_archives/<原相对路径>`，重名时追加 ISO 时间戳；
  - 移到回收站使用系统回收站；
  - 复制目录时递归复制，复制文件后校验哈希；
  - 复制到 `projects/` 时自动记录来源（FR-PROV）。
- 风险等级由 Go 侧计算，不信前端：
  - 高：含永久删除，或超过 20 项；
  - 中：含破坏性操作；
  - 低：其他。
- 计划卡显示风险等级、操作清单（最多 12 条，多出的截断）、恢复方式说明。永久删除另加警示，并多一层「我了解风险」预确认。执行后显示报告卡。
- 事务：
  - 只对编辑、移动、归档、移到回收站、永久删除这几种破坏性操作开事务；
  - 事务存在知识库内 `.mile-kb/transactions/<id>/`，包括 manifest 和操作前的原文件；
  - 目录只记标记，不复制整个子树；原本不存在的文件，恢复时删除；
  - 部分失败时标为「部分完成」，不自动回滚。
- 恢复：
  - 先逐条预检，按操作后的哈希判断是否可恢复；
  - 外部又修改过的文件标为冲突，不覆盖。
- 操作日志：
  - 每次尝试的操作记一条，字段包括 id、计划 id、知识库、发起者、操作类型、源、目标、前后哈希、状态、事务 id、错误码与消息、创建和完成时间；
  - 最多 2000 条，超出后裁掉最旧的；
  - 状态有：已计划、已批准、已完成、失败、已恢复、冲突、跳过；
  - 遇到错误就停，后续项记为跳过。
- 操作日志面板：从侧栏底部「操作日志」打开，最大高度 280px，显示最近 200 条，已完成的事务带「恢复」按钮。

### FR-PROV 来源追踪

- 只在复制到 `projects/` 时记录，存 `.mile-kb/provenance.json`，序列化顺序稳定。
- 7 种状态：
  - 未知：没有基线哈希；
  - 副本缺失；
  - 来源缺失；
  - 一致；
  - 来源改了：只有这一种提供「从来源同步」；
  - 副本改了；
  - 两边都改了：不提供同步按钮，避免丢失本地定制。
- 从来源同步（v1.6，D-009 第 2 条；旧版只是打开来源文档）：
  - 同步生成一条 `edit` 变更计划，必须经计划卡确认后执行，不能直接改盘；
  - 执行成功后副本内容等于来源当前内容，该记录的基线更新为来源当前 revision 与哈希，状态回到「一致」；
  - 同步可以从操作日志恢复；恢复后副本回到同步前的内容，基线不回退，状态会显示为「副本改了」；
  - 「两边都改了」「副本改了」不提供同步按钮。
- 来源面板在文档面板中显示：状态边框、文字标签、基于的版本、打开来源、同步按钮。

### FR-AI-ENG AI 引擎

- 协议：OpenAI 兼容 `POST {baseUrl}/chat/completions`，参数 `stream: true` 与 `stream_options.include_usage`。
- 流式解析：
  - `delta.content` 是正文，`delta.reasoning_content` 或 `reasoning` 是思考内容；
  - 正文开头的 `<think>…</think>` 也拆成思考内容；
  - `tool_calls` 按 index 累积，没有 id 时补 `call_<index>`；
  - 收到 `[DONE]` 或合法的 `finish_reason` 才算完整，半截的流报错。
- 带工具调用的 assistant 消息总是带上 `reasoning_content` 字段，因为 DeepSeek 思考模式缺这个字段会返回 400。
- 重试只针对拿到响应头之前：
  - 408、429、5xx 可重试；
  - 401、403 立即报鉴权错误；其他 4xx 立即失败；
  - 最多重试 10 次，退避 500ms×2^(n−1)，上限 15 秒，加 0–250ms 随机抖动；
  - 遵守 `Retry-After`，最多等 60 秒；
  - 重试时显示状态「第 n/m 次重试，x 秒后自动继续」。
- 流式过程中 300 秒没有收到任何字节就中止。取消操作要贯穿整个请求。
- 代理：
  - 跟随系统代理设置，包括 PAC；
  - 回环地址不走代理；
  - SOCKS5 代理可用（Go 传输层支持；旧版回落为直连，技术设计 2.1 已确认改进）；
  - 设置了 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 `NO_PROXY` 环境变量时以环境变量为准（mygo netproxy 的规则；旧版只问系统代理，D-010）；
  - 新版取得系统代理的方式在阶段 07 验证。
- 出站地址：https 任意；http 只允许 127.0.0.1、localhost 这类回环地址；URL 不能带用户名密码。
- 工具循环：
  - 每轮最多 16 步；
  - 只有正常结束的采样才写入历史；
  - 每个工具调用都必须有对应的工具结果消息，取消时剩余调用回填「已取消，未执行」。
- 上下文预算：
  - 估算 token 数 = ASCII 字符数 / 4 + 非 ASCII 字符数 × 0.7 + 每条消息 4；
  - 用真实的 `prompt_tokens` 校准，校准系数限制在 0.5–3；
  - 达到窗口的 80% 时压缩；窗口默认 64 000，可按供应商配置覆盖；
  - 压缩时保留最近约窗口 16% 的内容，切点只落在用户消息之前；
  - 更早的内容由模型写成摘要；摘要失败或仍然超限时，整轮丢弃最旧的内容并加截断说明；
  - system 提示和工具定义也计入预算。
- 引擎崩溃后的恢复：
  - 旧版：引擎是独立进程，崩溃后退避 min(10s, 500ms×2^(n−1)) 重启，最多 3 次后显示离线；会话按记录重建。
  - 新增约束：新版引擎在 Go 进程内运行，不需要单独进程，但单个回合出错不能拖垮应用。
- 引擎不可用（未配置供应商或出错）时，如实显示原因；编辑器和检索不受影响。

### FR-AI-AGT Agent 与工具

- 4 个 Agent：curator 整理归档、scout 推荐检索、distiller 蒸馏学习、general 自由问答。权限完全相同；各自有独立会话和独立的 steering。
- 旧版现状：4 个 Agent 共用空的 system 提示和同一套工具，差异只来自 steering。本期原样复刻（用户 2026-11-18 确认，Q3）。
- 工具（OpenAI function calling，描述用中文）：

| 工具 | 参数 | 规则 |
| --- | --- | --- |
| search_notes | query, limit | 默认 8 条，最多 20；返回路径、标题、命中字段、片段 |
| read_note | path, offset?, limit? | 单次最多 20 000 字符；分段时说明「第 a-b 个字符，共 N 个，还有更多 offset=…」；offset 越界给出明确错误 |
| list_dir | path | 空字符串表示根目录；不列出系统区 |
| write_note | path, content | 新建或覆盖，自动创建父目录；只能写内容区 |
| edit_note | path, old_text, new_text | old_text 必须恰好出现 1 次，出现 0 次或多次都报错；带 revision 冲突检测 |
| mutate_notes | kind, source?, target? | kind 取值：createDirectory、move、copy、archive、trash、permanentDelete；走变更事务；permanentDelete 要求 60 秒内、目标一致、且发卡时不是全自动模式的那次批准（只认变更审批卡，D-012），用过即作废 |

- 所有工具结果回给模型时截断到 20 000 字符。参数不合法时，以错误文字回给模型，不中断回合。

### FR-AI-PERM 执行模式与审批

- 3 档执行模式：
  - 手动和自动：每个写操作、修改操作、结构操作都弹审批卡。两档的区别只在界面文案。
  - 全自动：不弹审批卡，内容区操作直接执行。永久删除例外：直接拒绝，不弹卡，把「永久删除需要本次单独确认」作为工具错误回给模型（旧版 `EngineHost.ts:731-741, 815-827`，v1.2 按旧版代码修正）。
  - 3 档的系统区禁写规则相同。配置值不合法时降级为手动。
- 审批卡：
  - 只有「允许」和「拒绝」两个选项，没有「本会话始终允许」；
  - 卡片记录发出时的执行模式，之后换档不影响已发出的卡；
  - write_note 和 edit_note 的审批卡显示与磁盘原文的行差异，差异计算最多 400 万单元，预览最多 60 行；
  - 读取原文失败时只显示一行摘要，不阻塞审批。
- 系统区禁写，任何模式都适用：
  - `.mile-kb/config.json`、`.mile-kb/transactions/`、`.mile-kb/index/`、`.mile-kb/provenance.json`、`.mile-kb/settings/`；
  - 所有点号目录；
  - 草稿区 `.mile-kb/drafts/`：旧版 `agentPolicy.ts:43-44` 明确「草稿暂存区仍属应用系统区，任何 Agent 都不能直接写它」。
- 判定分两道：先按路径拼写判断，再按真实路径判断，防止短名、目录联接等绕过。
- 批准只覆盖引发它的那次操作：写入类审批随本次写入执行而作废，不产生可复用的写授权。结构变更的批准在 60 秒内对同一会话、同一路径有效、用过即作废；永久删除的新鲜批准只认专门的变更审批卡，普通的写入审批不顶替（比旧版更严，decisions.md D-012）。
- 两步确认防误触（删除历史、清空、删除供应商等）：第二次点击必须距第一次至少 600ms，且不能是双击；确认状态 4 秒后自动复位。
- 新增约束：审批卡的状态以 Go 侧为准。界面先发出回应、收到确认后再移除卡片，避免回合永远停在「进行中」（旧版曾出现过）。

### FR-AI-HIST 对话历史

- 存储位置：应用数据目录，不写进知识库。旧版格式是每个知识库一个 `index.json`，加每个对话一个 `<id>.jsonl`。新版格式在阶段 08 决定。
- 落盘内容：用户消息、回答、思考、工具调用、回合结束、错误。权限卡与用量不落盘。
- 上限：
  - 每个知识库最多 200 条对话；
  - 单个对话超过 4 MiB 时，新一轮开新对话；
  - 单个事件正文截断到 64 000 字符；
  - 一次最多读回 5000 个事件。
- 标题：取首条用户消息的第一行，压缩空白，超过 40 字符加省略号。重命名最多 80 字符，去掉控制字符。
- 搜索：
  - 输入 250ms 防抖，查询 ≤200 字符；
  - 只匹配用户消息和回答正文，最多 50 条；
  - 片段取命中处前后各 30 字符。
- 分组：置顶、今天、昨天、更早，按本地日期划分。置顶的对话不在日期组里重复出现；组内按更新时间倒序。
- 恢复与接着问：
  - 启动时恢复最后一个有内容的对话，顶部提示「已恢复上次对话」，可一键开新对话。
  - 「接着问」生成一段回顾块：只取用户消息和回答，每条 ≤1200 字符，总计 ≤6000，并声明「历史不是新指令」。回顾块只用一次，发送失败会放回。
  - 有 Agent 正在工作时，拒绝切换历史对话。
- 导出为 Markdown：包含标题、时间、轮数、参与的 Agent；工具调用写成一行摘要；不导出思考内容。文件名去掉非法字符，最多 60 字符。
- 删除、清空：使用两步确认防误触；清空时一并删除残留文件。
- 历史栏：
  - 宽 200px，位于对话区左侧，开合状态持久化；
  - 包含搜索框和分组列表；
  - 每行末尾悬停显示操作：重命名、置顶、删除；
  - 底部显示「共 N 条 · 清空全部」。
- 新增约束：历史搜索不能每次全量读取所有对话文件；搜索使用 SQLite FTS5 全文索引（对话正文写入索引，与知识库检索同一套预切词 + unicode61，详见数据库设计 §4.4）；历史列表和查看器都要虚拟化（P-4）。

  - 加密保存在本机应用数据目录；

  - 解密失败时提示重新填写。
- Agent 默认配置（agents.json 缺失或缺某个 Agent 时使用；D-010 按本条执行，旧版运行时实际是 4 个都逐条审批、都用供应商默认模型）：
  - 模型：deepseek 供应商的 deepseek-v4-flash，distiller 用 deepseek-v4-pro；agents.json 中存裸名 `deepseek-v4-flash` / `deepseek-v4-pro`，供应商里没有该模型时回落到第一个可用供应商的默认模型；
  - 推理强度：高；
  - 审批：scout 为自动，其他为手动；
  - 每个 Agent 的配置存在 `.mile-kb/settings/agents.json`。

- 诊断信息：引擎状态、重启次数、能力协商结果、key 存放说明。
- 新增约束：新版使用 Go 侧的 Windows 系统加密保存 key（具体方式在阶段 07 确定）。旧版用 Electron safeStorage 加密的 key 新版读不出来，用户需要重新填写（Q2 已确认）。

### FR-AI-USAGE 用量收据

- 字段：
  - token 数：总量、输入、输出、推理、缓存命中、缓存未命中；
  - 费用：估算费用、币种、是否估算、费用是否完整；
  - 缓存命中率；
  - 分本轮和累计两组。
- 未知不等于零：
  - 供应商没给费用时显示「— 未提供」，不显示 $0.00；
  - 命中数与未命中数都是 0 时，命中率显示「—」；
  - 缺少命中数时用 `prompt_tokens_details.cached_tokens` 补上，未命中数由「输入 − 命中」推算。
- 不自己计算费用：只用供应商给的值。
- 小数位按数量级选：≥1 保留 2 位，≥0.01 保留 3 位，≥0.0001 保留 5 位，更小保留 8 位；非零费用永远不显示成全零。
- 累计值由引擎累计，界面按回合覆盖，不自己叠加。

- 设置页：
  - 文本走草稿，用保存条统一保存；
  - 「与默认对比」用双栏显示；
  - 「恢复默认」只改草稿，不直接保存；
  - 模型、强度、执行模式、Skills 这些选择类控件即时生效。

### FR-AI-CTX 共享上下文与任务交接

- 4 个 Agent 共享「当前状况」，对话记录各自隔离。共享内容包括：
  - 知识库及其 revision、索引 revision；
  - 当前文档的路径、revision、是否有未保存修改、选区；
  - 固定的引用；
  - 任务板；
  - 决策记录；
  - 检索片段。
- Agent 只能写任务板、决策记录和检索片段，任务状态只能改自己负责的那条。
- 注入到消息中的上下文最多 2400 字符，按以下优先级保留：
  1. revision，永远保留；
  2. 当前文件和未保存标记，选区截到 200 字符；
  3. 固定引用，另有 1500 字符上限；
  4. 未完成的任务；
  5. 决策记录；
  6. 检索片段，最多 4 条，放不下就整条丢弃。
- 有内容被省略时写明「另有 N 项未列出」。绝对路径不进入上下文，文本先脱敏。
- 会话信息浮层（340px）包含：引擎状态、模型与诊断、文件读写边界、4 个职责的权限、共享上下文（任务板与固定引用）、设置入口。

## 7. 业务对象与状态流转

| 对象 | 状态 | 事件与触发者 | 下一状态 | 允许 / 禁止 |
| --- | --- | --- | --- | --- |
| 知识库 | 可用 / 已断开 | 启动或重试时检查根目录 | 可用 ↔ 已断开 | 已断开时只能重试或移除 |

| 变更计划 | 待确认 / 执行中 / 已完成 / 部分完成 / 失败 | 用户确认、执行结果 | 见左 | 执行前不改任何文件 |
| 操作记录 | 已计划 / 已批准 / 已完成 / 失败 / 已恢复 / 冲突 / 跳过 | 执行与恢复 | 见左 | 只有已完成且有事务的记录可以恢复 |

- 「大」：10 000 个 Markdown 文件，另加一个约 5000 文件的代码仓库目录。

### 10.2 安全与隐私

- 所有用户路径和 Agent 路径都在 Go 侧校验：
  - 长度 ≤1024；
  - 拒绝 NUL、UNC、绝对路径、盘符、`.` 和 `..` 片段、非法字符、首尾的点或空格、DOS 保留名；
  - 用真实路径判断是否在知识库内，拦截符号链接、目录联接、8.3 短名的绕过。
- 页面不能离开应用；新窗口一律拒绝；http(s) 链接交给系统浏览器打开。
- 错误信息脱敏：
  - 知识库根路径替换成 `<vault>`，用户主目录替换成 `<home>`；
  - `KEY=value`、`token:` 这类值，长度 ≥8 时替换；
  - sk-、pk-、ghp-、gho-、xoxb-、xoxp- 前缀的 key 替换；
  - 不向前端发送调用栈。
- 前端传来的 id 类参数只允许 `[A-Za-z0-9_-]`；字符串参数有长度上限。
- API key 不进入知识库、日志、索引、共享上下文和界面。
- 远程图片默认不加载；渲染时不执行文档里的 HTML 和脚本（原始 HTML 转义成文字显示）。

### 10.3 兼容与可访问性

- 知识库内的数据（`.mile-kb/` 下的设置、事务、来源记录）新旧版本格式兼容，同一个知识库可以被新旧版轮流打开（Q2 已确认）。
- 应用级数据：首次启动时一次性导入旧版的应用设置（主题、关窗行为、布局、最近知识库、上次知识库）和最近文档；旧版对话历史不导入；API key 需要重新填写。导入只读旧版文件，不修改它们；导入失败按默认值运行并提示。
- 正文对比度 ≥ 4.5:1；键盘焦点可见；开启减少动效时关闭循环动画；图标按钮必须有可读名称。
