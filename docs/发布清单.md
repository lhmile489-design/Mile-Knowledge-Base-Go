## 1. 范围与发布条件

- [ ] 发布范围、关联需求和当前计划明确。
- [ ] 本次业务验收、必要回归和安全检查完成，有实际证据。
- [ ] 阻断问题关闭；非阻断风险明确披露并获接受。
- [ ] 版本、执行者、批准范围和目标环境确认。
- [ ] WORKFLOW 的统一完成标准中本次发布适用项满足，项目质量门禁按技术设计执行；例外有明确批准且未过期。
- [ ] 所需独立审查、修复复验和整体集成检查有实际记录，不存在未经用户接受的阻断项。
- [ ] 标准、测试、断言、扫描和检查配置的变化已经专项核对，没有为通过发布弱化门禁。

## 2. 环境与安全

- [ ] 生产配置、密钥来源、外部服务与权限核实，不在文档写真实凭据。
- [ ] 适用的域名、TLS、跨域、网络与访问控制配置核实。
- [ ] 前后端产物、依赖和目标环境兼容性核实。
- [ ] 日志与诊断信息不泄漏敏感数据。
- [ ] 实际命令与配置适配目标平台和依赖版本，不直接照搬第三方 Skills 的包装命令与默认授权。

## 3. 数据与部署

- [ ] 前后端与数据变更顺序、兼容窗口和必要停机安排明确。
- [ ] 备份、迁移、初始化及实际执行命令核实，入口见根目录 README。
- [ ] 空库和适用旧版本升级路径已在非生产环境验证。
- [ ] 发布失败时的停止条件、责任人与沟通方式明确。

## 4. 回退与恢复

- [ ] 回滚、前向修复或备份恢复方式经过评估，不假定逆向 SQL 总是安全。
- [ ] 说明代码回退与数据回退能否独立执行、是否可能丢失数据。
- [ ] 恢复触发条件、步骤、前置资源、责任人和验证方式明确。
- [ ] 关键恢复路径有适用的验证证据，未演练部分明确标注。

## 5. 上线冒烟与观察

- [ ] 健康检查、日志、错误监控与必要告警可用。
- [ ] 先明确本次需要回答的运行问题，再选择适量信号；关键请求按需要有可关联标识，告警有可行动的处置说明。
- [ ] 新增监测或告警自身经过验证，未知或未测部分如实标注，不默认安装完整分布式观测套件。
- [ ] 适用的身份流程、核心读写、权限隔离、持久化和外部链路验证。
- [ ] PRD 的关键成功标准有上线观察方式。
- [ ] 部署成功与业务验证结果分别记录，不互相替代。
