# M8 T00 毛玻璃滚动性能 spike（2026-11-24）

> 结论：**本机上毛玻璃与不透明卡片没有可测差异**，200 张卡片滚动稳定在显示器刷新率（本机约 200 Hz，帧间隔中位数 5.0 ms）。门槛需要按刷新间隔换算，不能写死毫秒数。系统「动画效果」当前是开，WebView2 的 `prefers-reduced-motion` 与之一致；关闭状态未实测（改系统设置需要用户同意）。

## 方法

- 独立 spike 工程 `spikes/m8-glass/`：mygo v0.10.0 + WebView2 真窗口，静态页 `web/index.html`。页面复刻技能页的材质参数（卡片 18px 模糊 + 半透明底 + 顶部高光、页面底层三团 40px 模糊色场、200 张卡片三组）。
- 滚动：页面里 `window.__spike.start(6000)` 用 `requestAnimationFrame` 逐帧改滚动容器的 `scrollTop`，6 秒从顶滚到底，同时记录每帧间隔。停止后 `window.__spike.result()` 返回 `frames / p50 / p95 / max / slowRatio(>33ms)`。
- 驱动：`run.sh` 经 `MYGO_AUTOMATION` 的 eval 驱动（与 e2e 同一套 automation 插件），每个尺寸跑 3 轮 ×（毛玻璃开 / 关），每组前留 0.6 s 稳定时间。
- 尺寸：1440×900 与 960×720 各一个实例；实例带 `SPIKE_TAG`，驱动先确认页面标记与 200 张卡片都已就绪再测。
- 运行命令：`bash spikes/m8-glass/run.sh`。

局限：

- 脚本驱动的 `scrollTop` 每帧强制布局与绘制，和真实滚轮（合成器驱动）不完全相同；作为「同一页面上开 / 关毛玻璃」的对比口径是稳定的，绝对值偏保守。
- 窗口在测试期间可能处于后台；若 WebView2 对遮挡窗口降频，两组同受影响，对比结论仍成立。
- 未覆盖：4K 分辨率、150% 以上缩放、低端集显、超长卡片列表（>1000 张）。

## 门槛建议（按 B-M8-02 校准）

原草稿「p95 ≤ 20 ms」是按 60 Hz 写的；本机 200 Hz 下 20 ms 相当于 4 个刷新间隔，过松。改为按刷新间隔换算：

1. 进入技能页时先采一段空闲帧间隔，取中位数作为刷新间隔 `R`（本机 5.0 ms；60 Hz 屏幕为 16.7 ms）。
2. 滚动采样（200 张卡片）：
   - `scrollP95Frames = p95 / R`，门槛 **≤ 1.5**；
   - `slowFrameRatio = (帧间隔 > 2R 的比例)`，门槛 **≤ 5%**；
   - 记录绝对 p95 作参考（本机 5.1 ms）。
3. 进入技能页到首屏卡片可见：`enterP95Ms ≤ 300`（不变；spike 的 `loadEventEnd` 约 240 ms，含解析与首绘）。
4. 切回工作台第一帧 `≤ 100 ms`（沿用草稿，由 e2e 测）。
5. 自动降级（19.4）：进入页面后的前 120 帧采样里，若 `p95 > 2R` 且慢帧比例 > 5%，本运行内切到 `data-glass="off"`。按本机数据不会触发；60 Hz 上对应约 33 ms 的 p95。

## 对计划的影响

- 19.4 / 19.5 按上面的换算方式更新；`kind=m8` 的指标名改为 `scrollP95Frames`、`slowFrameRatio`、`enterP95Ms`、`switchBackMs`。
- 材质方案（卡片全部毛玻璃）保留，T08 按原计划实现；T12 用真页面重测，若真页面与 spike 差距大再降级。
- 未决：系统关闭动画效果后 WebView2 是否跟随，留给 T11 视觉任务时请用户帮忙切换一次系统设置验证（不擅自改）。
