# R-9 目录联接实测（R2 技能分发）

M4 开工前资料第 3 项（docs/PLAN-M0.md 3.5；docs/技术设计.md 13.4、13.5 第 3 条）。验证用目录联接（junction）把知识库技能分发到工具目录是否可行，以及删除、备份、扫描能否保证不跟随链接。

## 环境

- Windows 11 Pro for Workstations，go1.27.3 windows/amd64，`GODEBUG` 为空（`winsymlink`、`winreadlinkvolume` 取 Go 1.23 起的默认值）
- 依赖：`golang.org/x/sys v0.49.0`（与主模块同版本，模块缓存，无网络下载）
- 本机已开启开发者模式或有权限，`os.Symlink` 建目录符号链接可用（C5）；不同机器可能不可用，所以分发不依赖符号链接
- 所有用例都在 `os.MkdirTemp` 新建的临时目录里，名称含中文；跨盘用例在 D 盘的用户本地应用数据目录下另建临时目录。运行结束后两处都已清理，事后检查无残留。**没有读写任何真实工具目录。**

## 运行命令

```bash
export PATH="/c/Program Files/Go/bin:$HOME/go/bin:$PATH"
cd spikes/r9-junction
go vet .
go run .                    # 24 项
go run . -alt 'D:\<另一个卷上可写的目录>'   # 加跨盘 2 项，共 26 项
```

## 实现要点

- 创建：`os.Mkdir` 建空目录，`CreateFile(FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS)` 打开，`DeviceIoControl(FSCTL_SET_REPARSE_POINT)` 写入 `IO_REPARSE_TAG_MOUNT_POINT` 数据（替代名 `\??\<绝对路径>` + 显示名）；失败时删掉空目录。不启动子进程，不需要管理员。
- 识别：`GetFileAttributes` 看 `FILE_ATTRIBUTE_REPARSE_POINT`，再用 `FSCTL_GET_REPARSE_POINT` 读标签和目标，不依赖 `os.Lstat` 的模式位。
- 删除链接：先确认是联接或符号链接，再 `RemoveDirectory`；不是链接就拒绝。
- 遍历：自写 `safeWalk`，遇到任何重解析点都跳过，不进入、不读穿。

### Go 标准库的实际表现（C4、C9，供实现参考）

| 调用 | 对联接的结果 |
| --- | --- |
| `os.Lstat` | `ModeIrregular`，`IsDir()` 为 false，没有 `ModeSymlink` |
| `os.ReadDir` 的条目 | 同上，`IsDir()` 为 false |
| `os.Readlink` | 能读，目标正确 |
| `filepath.EvalSymlinks` | 能调用，但返回值与目标字符串不一致（大小写或短名形式）；**不要用它取目标** |
| `os.Stat` | 跟随到目标，`IsDir()` 为 true |
| `filepath.WalkDir` | 不进入联接（只把它当一个非目录条目） |
| `os.RemoveAll` | 遇到联接只删链接本身 |

现有的 `internal/vault/skillimport.go` 的 `walkSkill` 用 `entry.IsDir()` 与 `Type().IsRegular()` 判断，联接两者都不满足，会被跳过，所以技能导入不会读穿联接。

### 扫描耗时（C18）

本机工具目录合计约 700 个条目。基准：350 个真实目录 + 350 个联接，每个条目做识别 + 读 `SKILL.md` 前 4 KiB。

| 运行 | 5 次耗时 |
| --- | --- |
| 第 1 次（带跨盘） | 中位 68ms，最大 2.34s |
| 第 2 次 | 733ms 80ms 60ms 66ms 61ms |
| 第 3 次 | 107ms 82ms 80ms 84ms 76ms |

文件刚写完的第一遍偏慢（推测是杀毒软件扫描新文件），之后稳定在 60–85ms。建 350 个联接 88–128ms（每个约 0.3ms）。

## 结论

**通过**（用户 2026-11-20 审核）：目录联接可以作为默认分发方式；不需要管理员，跨本地卷可用，中文路径可用；Go 1.27 默认设置下 `os.RemoveAll`、`WalkDir` 不跟随联接。

两条必须写进实现的规则：

1. **建之前校验目标**：内核不检查目标。指向不存在的目录或 UNC 路径都能「建成功」，但 UNC 的联接一访问就报「重解析点缓冲区数据无效」。如果只看创建是否成功，退回拷贝的逻辑不会触发。所以创建前要求目标是本地绝对路径、存在且是目录；创建后用 `os.Stat` 经链接读一次，失败就删掉链接、退回拷贝。
2. **识别与删除不靠模式位**：`os.Lstat` 对联接的表现在 Go 1.23 变过，以后还可能再变；识别用重解析标签，删除用「确认是链接后 `RemoveDirectory`」。另外加一条回归测试：`os.RemoveAll` 作用于含链接的目录时，链接目标的哈希不变（C8），防止将来 Go 或 `GODEBUG` 设置改变行为。

## 未测与剩余风险

- 各工具是否认联接加载技能：本 spike 不碰真实工具目录，没测。技术设计 13.5 第 3 条的人工验证需要在真实工具目录里装测试技能，**执行前单独征得用户同意**。
- 权限不足（目标目录 ACL 拒绝）、FAT32 / exFAT 卷（不支持重解析点）、映射网络盘的盘符、OneDrive 占位目录、超过 260 字符的路径：没测。这些情况下创建会失败或第 1 条的经链接读会失败，应走退回拷贝；M4 实施时用注入的失败覆盖这条路径。
- 杀毒软件对首次扫描的影响只观察到一次 2.34s 的峰值，没有定位。M4 的扫描要先显示缓存结果、后台刷新（PRD FR-SKM-SCAN 已要求）。
